Importing a Codebase

Already have a project on GitHub? Start from it instead of a blank slate.

Why Import Instead of Prompt?

Not every project starts from zero. If you've already got a public GitHub repo — a side project, a prototype, something you started elsewhere — you can bring it straight into Gor://a and keep building with the agent instead of re-describing it from scratch.

How It Works

From the Dashboard, click the GitHub icon next to the prompt bar and paste the repo URL. Gor://a will:

  1. Download the repo: Pulls the default branch (falling back to master if there's no main) directly from GitHub — no authentication needed for public repos.
  2. Filter the noise: Skips node_modules/, build output, lockfiles, and binary assets, keeping only the source files that actually matter to the agent.
  3. Seed your project: Writes every remaining file into your new project before the sandbox ever boots, so the agent's first turn already sees your real file tree.

The First Turn Is Read-Only: On import, the agent's first response is a quick orientation pass — it reads through your codebase and summarizes what it found (tech stack, structure, what the app does) without touching anything. It waits for your next instruction before making any changes, so you don't come back to a codebase that's already been rewritten out from under you.

Limitations

  • Only public repositories are supported right now — private repo import isn't available yet.
  • Very large repos are capped at a few hundred files and a per-file size limit, so massive monorepos will only bring in a relevant subset.
