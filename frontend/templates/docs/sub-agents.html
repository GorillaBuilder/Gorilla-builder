Delegating Sub-Tasks

For bounded investigations that shouldn't clutter the main conversation.

The Problem With One Long Conversation

Some requests need a chunk of exploratory back-and-forth before there's anything worth telling you — "figure out why the checkout form silently fails" might take a dozen file reads and a few failed hypotheses before landing on the actual bug. Dumping all of that into the main chat makes it noisy and burns context that would be better spent on the actual fix.

How Gor://a Handles It

For self-contained investigations, the agent can delegate to a fresh sub-agent scoped to just that task. The sub-agent works in the same project sandbox — same files, same running dev server — but starts with a clean slate and reports back only a summary: what it found, which files it touched, and its conclusion.

What you'll see: A "Delegating…" activity card appears in the chat, just like a file read or a command run. Expand it to see what the sub-agent did — you don't have to wait for it to finish before you can see it's in progress.

Guardrails

Delegation is intentionally bounded so it can't spiral into a runaway loop:

  • One level deep: A sub-agent cannot itself delegate further — it works with the direct tools (read, write, run commands) only.
  • Turn-capped: Each delegation runs for a handful of turns at most before it has to report back, whether or not it's fully "done."
  • Token-metered: Sub-agent work is billed against your token balance exactly like any other agent turn — delegation doesn't make work free, it just keeps your main conversation focused.
